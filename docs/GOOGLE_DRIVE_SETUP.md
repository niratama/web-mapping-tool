# Google Drive 連携用 OAuth クライアント ID 取得・設定ガイド

本ドキュメントは、**GridMap Studio** で Google Drive 保存・読み込み機能を利用するために必要な **OAuth 2.0 クライアント ID** の取得手順書です。

- **利用料金**: **完全無料 (0円)**（Google Cloud の無料枠内で無期限に利用可能・クレジットカード登録も不要）
- **Google 審査**: **不要**（最小権限スコープ `drive.file` を使用するため、数週間かかる面倒な審査なしで即日利用可能）
- **必要なもの**: 通常の Google アカウント（Gmail アドレス）1 つ

---

## 📋 全体の流れ

1. **[共通] Google Cloud プロジェクトの作成 & Drive API 有効化** (約3分)
2. **[共通] Google Auth Platform (OAuth 同意画面) の初期構成** (約2分)
3. **[公開向け] ブランディング設定 (アプリドメイン・承認済みドメイン・ロゴ設定の注意点)** (約3分)
4. **[最重要] スコープ（データアクセス）の設定 (`drive.file`)** (約1分)
5. **[パターン別] クライアント ID の作成**:
   - **パターン A: 公開サイト用（本番: `nira.poi.jp` / GitHub Pages）**
   - **パターン B: ローカル環境用（開発・セルフホスト用: `localhost:8000`）**
6. **[公開向け] アプリの公開（テスト中から本番環境への切り替え）**

---

## ステップ 1: プロジェクトの作成 & Drive API の有効化 (共通)

1. **Google Cloud Console にアクセス**:
   - [https://console.cloud.google.com/](https://console.cloud.google.com/) をブラウザで開きます。
2. **新しいプロジェクトを作成**:
   - 画面上部のプロジェクト選択プルダウンをクリックし、右上の **「新しいプロジェクト」** をクリックします。
   - プロジェクト名: `GridMap Studio`（任意の名前で可）
   - 「作成」をクリックし、作成されたプロジェクトに切り替えます。
3. **Google Drive API を有効化**:
   - 左側メニューの **「API とサービス」** > **「ライブラリ」** を開きます。
   - 検索バーに `Google Drive API` と入力して検索します。
   - **「Google Drive API」** を選択し、**「有効にする」** ボタンをクリックします。

---

## ステップ 2: Google Auth Platform (OAuth 同意画面) & ブランディングの設定

ユーザーが「Google ログイン」を押した際に表示される認証確認画面、アプリ情報、および利用スコープを設定します。

### 2-1. 初期構成ウィザード（初回のみ）

1. **同意画面を開く**:
   - 左側メニューの **「API とサービス」** > **「OAuth 同意画面」**（または **「Google Auth プラットフォーム」**）をクリックします。
2. **「Google Auth Platform はまだ構成されていません」と表示された場合**:
   - **「開始」** ボタンをクリックし、初期フォームを入力します:
     - **① アプリ情報**: アプリ名 `GridMap Studio`、サポートメールをご自身のアドレスに設定
     - **② 対象**: **「外部」** を選択（個人の Google アカウントでは外部を選びます）
     - **③ 連絡先情報**: ご自身のメールアドレスを入力
     - **④ ポリシーへの同意**: チェックを入れる
     - **⑤「作成」ボタン** をクリックします。

---

### 2-2. ブランディング設定（公開・本番運用向け）

一般公開（外部のユーザーもログインして保存できるようにする）に向けて、アプリのドメインや連絡先情報を整えます。
左側メニューの **「ブランディング」**（従来のUIでは「OAuth 同意画面」の編集画面）を開きます。

| 設定項目 | 推奨入力値 | 説明・注意点 |
| :--- | :--- | :--- |
| **アプリ名** | `GridMap Studio` | 認証ダイアログの上部に表示される名称です。 |
| **ユーザー サポートメール** | ご自身の Gmail アドレス | ユーザーからの問い合わせ先メールアドレスです。 |
| **アプリのロゴ** | **【空欄のまま推奨】** | ⚠️ **ロゴをアップロードすると Google による商標等のブランディング審査（数日〜数週間の審査待ち）が必須になります。** 空欄のままであれば審査なしで即座に本番公開可能です。 |
| **アプリのホームページ** | `http://nira.poi.jp` または `https://niratama.github.io/web-mapping-tool/` | アプリが公開されているトップページの URL を入力します。 |
| **アプリのプライバシー ポリシーのリンク** | `http://nira.poi.jp` または `https://github.com/niratama/web-mapping-tool` | 本番公開するために必須の項目です。公開サイトまたは GitHub リポジトリ（README）の URL を指定します。 |
| **アプリ利用規約のリンク** | （空欄で可） | 任意項目です。必要に応じてリポジトリ等のリンクを設定できます。 |
| **承認済みドメイン (Authorized Domains)** | `poi.jp` / `github.io` | 下記の手順で登録します。 |
| **デベロッパーの連絡先情報** | ご自身のメールアドレス | Google からの重要通知（API規約変更等）を受け取るアドレスです。 |

> [!IMPORTANT]
> **「承認済みドメイン」の登録方法**:
> - 「承認済みドメイン」欄の **「+ ドメインを追加」** をクリックします。
> - ホームページやプライバシーポリシーに指定したドメインを登録します（例: `poi.jp`、`github.io`）。
> - ※ `http://` や `/` などの記号・パスは含めず、ドメイン名のみを入力します（例: `nira.poi.jp` ではなく `poi.jp` を入力）。
> - ※ `localhost` はここには入力不要（登録不可）です。

入力が完了したら、画面最下部の **「保存」** をクリックします。

---

### 2-3. スコープ（データアクセス）の設定 (最重要)

1. 左側メニューの **「データアクセス」**（従来のUIでは「スコープ」）をクリックします。
2. **「スコープを追加または削除」** ボタンをクリックします。
3. フィルタ検索欄に `drive.file` と入力し、以下のスコープにチェックを入れます:
   - `.../auth/drive.file`（「Google ドライブの選択したファイルの表示、編集、作成、削除」）
4. 画面下の **「更新」**（または「保存して次へ」）をクリックします。

> [!IMPORTANT]
> 必ず `drive.file` を選択してください。広域の `drive` や `drive.readonly` を選ぶと Google の厳格なセキュリティ審査（セキュリティ診断書の提出等）が必須になりますが、`drive.file` であれば**審査不要**で即座に本番公開可能です。

---

### 2-4. 本番公開への切り替え（アプリの公開）

初期状態では公開ステータスが **「テスト中」** になっています。「テスト中」のままだと、登録したテストユーザー（最大100人）しかログインできず、トークンも7日間で切れてしまいます。一般公開サイトとして運用する場合は「本番環境」に切り替えます。

1. 左側メニューの **「対象ユーザー」**（または **「ダッシュボード」**）を開きます。
2. 公開ステータス欄にある **「アプリを公開」** ボタンをクリックします。
3. ポップアップで確認を求められるので **「確認」** をクリックします。
4. ステータスが **「本番環境（In Production）」** に変われば完了です！

> [!TIP]
> 上記の通り「ロゴ未登録」かつ「`drive.file` スコープのみ」であれば、**Google による審査や審査待ちは一切発生せず、ボタンを押した瞬間に即時公開**されます。

---

## ステップ 3: OAuth クライアント ID の発行

ここから利用形態（本番公開サイト用 か localhost用 か）に合わせてクライアント ID を作成します。

---

### 【パターン A】公開サイト用 (本番ドメイン: `nira.poi.jp` / GitHub Pages)

本番公開サイトで一般ユーザーが設定不要でワンクリック保存できるようにするための公式 Client ID です。

1. **クライアント作成画面を開く**:
   - 左側メニューの **「クライアント」**（または **「API とサービス」** > **「認証情報」**）を開きます。
   - 上部の **「+ クライアントを作成」**（または **「+ 認証情報を作成」>「OAuth クライアント ID」**）をクリックします。
2. **設定内容の入力**:
   - **アプリケーションの種類**: `ウェブ アプリケーション`
   - **名前**: `GridMap Studio (Production)`
   - **承認済みの JavaScript 生成元 (Authorized JavaScript origins)**:
     以下の「+ URI を追加」をクリックして登録します:
     - `http://nira.poi.jp`
     - `https://niratama.github.io`
   > [!CAUTION]
   > 本番用の生成元には **`localhost` を絶対に含めないでください**。登録しないことで、第三者が本番用の Client ID をコピーして自分の PC で悪用することを完全に遮断できます。
3. **発行と保存**:
   - 「作成」をクリックすると、ポップアップに **「クライアント ID」**（例: `xxxxxxxxxxxx-xxxxxxxxxxxxxxxx.apps.googleusercontent.com`）が表示されます。
   - これをコピーして控えておきます（クライアント シークレットは本アプリでは不要です）。

---

### 【パターン B】ローカル開発・セルフホスト用 (`localhost:8000`)

自身のローカル環境（PC上）で `npm run serve` や `python3 -m http.server 8000` 等を使って動かす開発者用の Client ID です。

1. **クライアント作成画面を開く**:
   - 左側メニューの **「クライアント」**（または **「API とサービス」** > **「認証情報」**）を開きます。
   - 上部の **「+ クライアントを作成」**（または **「+ 認証情報を作成」>「OAuth クライアント ID」**）をクリックします。
2. **設定内容の入力**:
   - **アプリケーションの種類**: `ウェブ アプリケーション`
   - **名前**: `GridMap Studio (Localhost)`
   - **承認済みの JavaScript 生成元 (Authorized JavaScript origins)**:
     - 「+ URI を追加」をクリックし、`http://localhost:8000` を追加（※ 末尾のスラッシュ `/` は付けません）
     - （※ 必要に応じて他のポート `http://localhost:3000` や `http://127.0.0.1:8000` を追加）
3. **発行と利用**:
   - 「作成」をクリックし、表示された **「クライアント ID」** をコピーします。

---

## 🔧 GridMap Studio での設定反映方法

### 1. 本番サイトのデフォルト ID 設定（コード側）
発行したパターン A（本番用 Client ID）を、コード内の設定定数に反映します:

```javascript
// js/gdrive.js
PRODUCTION_CLIENT_ID: 'xxxxxxxxxxxx-xxxxxxxxxxxxxxxx.apps.googleusercontent.com',
```

### 2. ローカル実行時（UI 側）
1. ローカルで起動した GridMap Studio（`http://localhost:8000`）を開きます。
2. 画面上部ヘッダーの **「クラウド」** ボタンをクリックします。
3. クラウドマネージャーモーダルの右上にある **設定アイコン（⚙️）** をクリックします。
4. パターン B で取得した Client ID を入力して **「設定を保存」** をクリックします。
5. 「Google でログイン」をクリックして認証します（ID はブラウザの `LocalStorage` に安全に保持され、次回以降も自動適用されます）。

## ❓ よくある質問とトラブルシューティング (FAQ)

### Q1. ログイン時に `400: origin_mismatch` というエラーが出る
- **原因**: アクセスしている現在の URL（例: `http://localhost:8000`）が、Google Cloud Console の「承認済みの JavaScript 生成元」に完全一致で登録されていません。
- **対処**:
  - プロトコル（`http://` または `https://`）、ポート番号（`:8000`）、末尾のスラッシュの有無を確認してください（※ 末尾に `/` は含めず `http://localhost:8000` と登録します）。

### Q2. ログイン時に「このアプリは Google で確認されていません」と表示される
- **原因**: アプリの公開ステータスが「テスト中」のまま、または Google によるブランド確認が行われていない場合に表示されます。
- **対処**:
  - ステップ 2-6 の通り、OAuth 同意画面で **「アプリを公開」** をクリックして本番環境に切り替えてください。
  - 警告画面が出た場合でも、画面左下の「詳細」をクリックし、**「GridMap Studio（安全ではないページ）に移動」** をクリックすればそのまま認証を完了して利用できます（自分専用の Client ID なのでセキュリティ上全く問題ありません）。

### Q3. このアプリを使うと、ドライブ内の他のファイルが見られてしまう心配はありませんか？
- **答え**: **一切ありません。**
  - 要求スコープが `https://www.googleapis.com/auth/drive.file` に制限されているため、Google のセキュリティポリシー上、このアプリは「GridMap Studio が作成したファイル（専用フォルダ `GridMapStudio/` 内）」以外には読み取りも書き込みも一切アクセスできません。プライベートな文書や写真等が見られることは不可能です。
